1.
Stands up the floor plan from scratch in a new environment: the mat records
themselves plus their layout, which nothing in the repo could do before.
Reset Mat Layout only restores mats that already exist.

Manual trigger, with an optional Mat plan name (blank = Floor Plan). It finds
that plan, creates it if absent, then creates each of the 117 mats unless one
with the same label is already on the plan, so it is safe to re-run.

Each mat is created with label, number, X/Y, Default X/Y set to the same
values, width, height, gender, Render = Yes, Standard Mat = Yes, Client Mats
and the plan link. Fill and stroke are left alone -- they are formula columns
that compute themselves. The three Overflow mats are excluded as they are not
part of the default plan.

The configuration is embedded in the flow rather than read from anywhere,
since the target environment has no mats yet. It was taken from the sandbox
after the layout was reset, so it matches the floor plan exactly.

Verified in the sandbox: a run with all 117 present created nothing; deleting
OPS and mat 29 and re-running recreated both with every field identical and
the colour formulas recomputed.

6.
The Shelter Client form had no single place to see a client's history across
programmes: Detox admissions, Boreal intakes and Shelter check-ins each live
in their own table.

ServiceTransactions is a dataset control that reads all three directly for the
client whose form it sits on, unions them, and lists them newest first with
Start Date, End Date, Provider of Service, Service Type and Stay. Dates map
per table: cp_admissiondate/cp_actualdischargedate, ahb_dateofintake/
ahb_programexitdate, cp_checkindate/cp_checkoutdate. Service Type is fixed by
programme -- Detox, Emergency Shelter, Transitional Housing. It also has a
date-range filter with presets, paging, per-programme counts, and a pencil
that opens the stay itself.

Each table is queried separately so a user without access to one programme
still sees the others, with a note about what is missing.

The control ignores its dataset; it only needs a subgrid to host it. On this
form that host is a contact subgrid over the Active Clients view -- a view the
Shelter app includes, which is what the host needs to be. The dataset property
is still named cp_servicetransaction, after a table since removed.

9.
Medication Administration Records (MAR), Detox solution. The paper MAR sheets
move into Dataverse as five new tables, all user-owned and audited except the
medication list:

  cp_marsheet                  one paper sheet (or Home/Insulin medication
                               block) per admission; cp_sheettype picks which
                               of the 11 sheets it is (global choice
                               cp_marsheettype)
  cp_medicationadministration  one dose / grid entry on a sheet
  cp_medicationreconciliation  the nightly count, refusals, two staff IDs
  cp_marday                    a titration/taper day box: instruction and
                               START / STOP
  cp_detoxmedication           organization-owned list of medications for the
                               PRN (OTC) sheet, seeded with Ibuprofen (Advil),
                               Acetaminophen (Tylenol) and Ginger Gravol;
                               nurses add others from the sheet

Shared columns cover what the sheets have in common (dose, amount, count,
2 mg / 8 mg counts, BP, HR, notes, staff); cp_ii_* and cp_po_* columns hold the
insulin- and PRN-only fields. cp_marsheet.cp_frequency comes from the updated
HOME MEDS template. Admission -> MAR Sheet -> dose / reconciliation / day are
Restrict-delete; the shortcut lookups to Admission and cp_staff are
RemoveLink. MAR Sheet's Sheet Type and Admission map onto new child records.
cp_detoxmedication was added to the Detox app.

cp_medicationadministration.cp_po_medication (a fixed choice) is superseded by
the cp_detoxmedication lookup and holds no data; it is left in place pending a
decision to delete it.

Built by scripts/mar/build_mar_schema.py (tables, columns, relationships, app
component, medication seed rows) and scripts/mar/build_mar_forms.py (views,
mappings, main forms, the MAR Client Header admission quick view, and the
Medications tab on the Detox Admission form). Both are re-runnable. The MAR
Sheet main form is now arranged by hand in the maker portal (Sheet Type above
the control), so the forms script only creates that form if it is missing.

10.
MAR Sheet control (PCF/MarSheet, cp_AlphaHouse.MarSheet, v0.1.15). Sits on the
MAR Sheet form bound to cp_name and draws the sheet as its paper layout; every
line a nurse fills in is saved as its own record:

  12 date boxes + reconciliation    Methadone/Kadian Maintenance, High-Risk
                                    Controlled, Benzodiazepine Maintenance,
                                    Suboxone Maintenance (2 mg / 8 mg)
  8 boxes with day instruction      Methadone/Kadian Titration, Suboxone
                                    Titration
  DAY ONE..EIGHT with START / STOP  Benzodiazepine Taper (8-Day), Benzodiazepine
                                    Taper (Pre-filled 5-Day: QID QID TID BID OD,
                                    stop on day 6, BP only)
  medication rows                   PRN (OTC) from cp_detoxmedication with a
                                    daily maximum per medication; General (Home)
                                    MAR and Insulin Injection Log, one block per
                                    sheet

ID / initials default to the cp_staff record whose cp_email matches the
signed-in user. Total daily dose, the 3-refusal banner and PRN daily totals are
computed live; cp_refusalcount is kept in step from reconciliation refusals.
A PRN dose over the daily maximum cannot be saved. Insulin entries need a B.G.
level, a site when a dose is given, and a note when held; B.G. under 4.0 mmol/L
shows red.

Each layout was tested in the sandbox with Playwright against a synthetic
client, admission and sheets that were deleted afterwards.

11.
Deploying the control. pac pcf push from a OneDrive-synced folder can fail with
"Access to the path ...obj\PowerAppsToolsTemp_cp\bin\Debug is denied": delete
obj\PowerAppsToolsTemp_cp and push again (see
read-before-deploying-pcf-vscode-to-pp.txt). Bump the version in
ControlManifest.Input.xml on every push.

After a push the app can load the new bundle.js with the old MarSheet.css: web
resources are cached under a {ticks}/webresources path held in the browser's
Cache Storage and service worker, and neither the push's Publish All nor a
further publish moves it for an open client. Staff may need a hard refresh
after a release.

13.
Vital Signs sheet (Vital Signs, CIWA/COWS, Urine/Blood Testing Results
Record), MAR Sheet control v0.1.16. cp_marsheettype gains Vital Signs
(121570011); build_mar_schema.py now adds missing options to the existing
global choice, so it stays re-runnable.

Each ruled row is a cp_medicationadministration, like every other sheet. BP,
HR and blood glucose reuse cp_bp, cp_hr and cp_ii_bglevel. New columns:
cp_vs_respiratoryrate, cp_vs_oxygensaturation, cp_vs_temperature,
cp_vs_cowsscore, cp_vs_ciwascore, cp_vs_hcgresult (Negative / Positive /
Declined) and cp_vs_drugtestresult (positive results only). The Medication
Administration form has a "Vital Signs only" section for them.

The first row shows the admission's own intake readings, read from the
admission rather than copied: cp_admissiondate, cp_bp, cp_hr, cp_o2sats,
cp_temp, cp_cowsscore1, cp_ciwascore1 and Staff Completing Medical Portion.
It is read-only on the sheet; edit it on the admission's Medical1 and
Withdrawal tabs. The admission has no respiratory rate, so that cell is
blank, and the CIWA/COWS Score 1 formula columns show 0 when no assessment is
linked.

A reading needs date, time, nurse initials and at least one value; numbers
are range-checked, and a positive HCG or a B.G. under 4.0 mmol/L shows red.
Tested in the sandbox with Playwright against a synthetic client, admission
and sheet that were deleted afterwards.
