1.
Stands up the floor plan from scratch in a new environment: the mat records
themselves plus their layout, which nothing in the repo could do before.
Reset Mat Layout only restores mats that already exist.

Manual trigger, with an optional Mat plan name (blank = Floor Plan). It finds
that plan, creates it if absent, then creates each of the 117 mats unless one
with the same label is already on the plan, so it is safe to re-run.

Each mat is created with label, number, X/Y, Default X/Y set to the same
values, width, height, gender, Render = Yes, Standard Mat = Yes, Client Mats
and the plan link. Fill and stroke are left alone -- they are formula columns
that compute themselves. The three Overflow mats are excluded as they are not
part of the default plan.

The configuration is embedded in the flow rather than read from anywhere,
since the target environment has no mats yet. It was taken from the sandbox
after the layout was reset, so it matches the floor plan exactly.

Verified in the sandbox: a run with all 117 present created nothing; deleting
OPS and mat 29 and re-running recreated both with every field identical and
the colour formulas recomputed.

staff re-entered what was already recorded against the check-in.

6.
The Shelter Client form had no single place to see a client's history across
programmes: Detox admissions, Boreal intakes and Shelter check-ins each live
in their own table.

ServiceTransactions is a dataset control that reads all three directly for the
client whose form it sits on, unions them, and lists them newest first with
Start Date, End Date, Provider of Service, Service Type and Stay. Dates map
per table: cp_admissiondate/cp_actualdischargedate, ahb_dateofintake/
ahb_programexitdate, cp_checkindate/cp_checkoutdate. Service Type is fixed by
programme -- Detox, Emergency Shelter, Transitional Housing. It also has a
date-range filter with presets, paging, per-programme counts, and a pencil
that opens the stay itself.

Each table is queried separately so a user without access to one programme
still sees the others, with a note about what is missing.

The control ignores its dataset; it only needs a subgrid to host it. On this
form that host is a contact subgrid over the Active Clients view -- a view the
Shelter app includes, which is what the host needs to be. The dataset property
is still named cp_servicetransaction, after a table since removed.
